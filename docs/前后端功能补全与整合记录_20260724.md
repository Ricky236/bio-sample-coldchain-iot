## 3. 本分支新增与保留的后端能力

为兼容当前小程序已完成页面，在新后端基础上重新接入：

- `POST /api/v1/devices/{device_id}/bind-check`
  - 创建运单前检查设备是否已被其他任务占用。
- `GET /api/v1/devices/{device_id}/precheck`
  - 从真实硬件聚合接口读取最新温湿度、箱体状态。
  - 默认不使用本地测试数据代替真实数据。
  - 校验数据新鲜度、温控范围和箱体关闭状态。
- `POST /api/v1/devices/{device_id}/simulate-reading`
  - 仅在 `ALLOW_LOCAL_SIMULATION=1` 时开放，用于无硬件联调。
- `GET /api/v1/tasks/{task_id}/hardware/snapshot`
  - 代理 `http://47.103.152.175:8080/api/v1/admin/live-snapshot`。
  - 只返回与任务号或绑定设备号严格匹配的数据。
- `POST /api/v1/face/simulate-verify`
  - 仅在 `ALLOW_LOCAL_SIMULATION=1` 时开放，用于开发工具联调。

此外修复了 Windows 测试中的 SQLite 连接释放：

- 请求内连接由中间件统一关闭。
- 脚本或测试直接调用数据库时，上下文退出后立即关闭连接。
- 测试中的原生 SQLite 连接改为“提交后显式关闭”，避免下一用例无法删除临时数据库。
- 兼容旧数据库中以文本保存的 `owner_user_id`、`carrier_user_id`、`receiver_user_id`，
  避免同一用户因 `"5"` 与 `5` 类型不同而被错误返回 404。

## 4. 小程序前端改动

### 4.1 运单创建与编辑

文件：`miniprogram/src/pages/create/index.vue`

- 承运人和接收人不再手工填写文本。
- 分别调用：
  - `GET /api/v1/users?role=carrier`
  - `GET /api/v1/users?role=receiver`
- 使用已注册且启用的真实账号进行选择。
- 创建流程调整为：

  1. `POST /api/v1/tasks` 创建固定运单号；
  2. `POST /api/v1/tasks/{task_id}/assign` 分配承运人和接收人；
  3. `POST /api/v1/devices/{device_id}/bind` 绑定设备；
  4. `POST /api/v1/tasks/{task_id}/precheck` 保存首条预检结果。

- 创建任务时不再直接提交 `device_id`，符合后端安全约束。
- 修改运单由旧 `PUT` 改为 `PATCH /api/v1/tasks/{task_id}`。
- 草稿中保存候选账号 ID，恢复草稿时重新匹配真实账号。
- 保留扫码读取设备、箱体、封签信息。

### 4.2 交接与动态二维码

文件：`miniprogram/src/services/tasks.ts`

- 增加 `listHandoffs`，调用 `GET /api/v1/tasks/{task_id}/handoffs`。
- 创建二维码前创建真实交接会话。
- 如果交接会话已存在，则读取当前待处理会话，不重复创建。
- 后端返回 `ttl_seconds`、`handoff_id` 和可直接展示的 PNG Data URL，真机可扫码。
- 兼容新后端的 `from_user_id`、`to_user_id` 和 `evidence` 字段。
- 二维码核验后再允许接收方进行人脸流程和责任确认。

### 4.3 人脸流程

- 真机仍通过微信 `camera` 组件拍摄正脸。
- 首次使用时创建当前账号的人脸档案，随后调用 `POST /api/v1/face/verify`。
- 后端当前使用“活体是否通过 + 相似度分值 + 人工复核状态”的联调模型。
- 开发者工具无法提供真实 Camera 画面时，可在开启本地模拟后调用模拟接口。

> 注意：当前实现是竞赛联调流程，不等同于商业级生物特征识别。正式上线应接入合规的人脸识别服务，取得单独授权同意，并按最小化原则保存模板和审计记录。

## 5. 安全与运行开关

建议生产环境：

```env
ALLOW_LOCAL_SIMULATION=0
ALLOW_ADMIN_SELF_REGISTER=false
LIVE_SNAPSHOT_URL=http://47.103.152.175:8080/api/v1/admin/live-snapshot
PRECHECK_MAX_DATA_AGE_SECONDS=120
```

本地无硬件联调时才设置：

```env
ALLOW_LOCAL_SIMULATION=1
```

小程序真机访问局域网后端时，手机与电脑必须在同一网络，后端监听 `0.0.0.0`，并将小程序 API 地址设置为电脑局域网 IP。正式发布时必须使用已备案的 HTTPS 合法域名。

## 7. 联调顺序

1. 启动后端并初始化管理员。
2. 分别注册发货方、承运方、接收方账号。
3. 发货方创建运单并选择承运人、接收人。
4. 绑定设备并执行真实预检。
5. 发货方生成动态二维码。
6. 指定承运人扫码、完成人脸流程并确认交接。
7. 运输中查看实时监控与告警。
8. 到达后创建承运方到接收方交接。
9. 指定接收人扫码、完成人脸流程。
10. 上传验收证据并签收或拒收。
11. 在责任追溯页查看交接节点、异常、证据和报告。
